# 題庫檢視與共用外框 — 設計文件

日期：2026-08-21（版面與字級部分於同日修訂）

> **詞彙**：本文件依 [`CONTEXT.md`](../../../CONTEXT.md) 用詞 —— 題庫、科目、章、題、朱批。「卷」「章節」「Dashboard」「體檢表」皆已除役。

## 背景

`2026-08-16-quiz-bank-design.md` 把題庫區規劃成編輯台：四個路由的 CRUD、透過 File System Access API 寫回 `public/data/`、只能在本機 `npm run dev` 使用。測驗區已依該文件實作完成，題庫區尚未動工。

這次釐清後，題庫區的職責整個變了。題目由上游的 skill + LLM 生成與校對，寫進 repo 的 JSON 是**產出物而非原稿**；要改就回上游改完重出整章。前端因此不需要校對介面、不需要編輯表單、不需要匯入功能，連科目與章的結構管理也交給上游。**全站零寫入**（見 [ADR-0001](../../adr/0001-bank-is-generated-upstream.md)）。

## 修訂說明

本文件的第一版做出的版面決定在實作後被推翻。實際跑起來有兩個問題：

1. **版面沒佔滿畫面。** 容器被壓在 `max-width: 960px`，1920px 螢幕只用一半、2560px 只用 37%。960px 是**閱讀**的寬度，套在測驗頁是對的，但題庫區是**掃視**介面，被綁在同一個容器上等於讓報表穿了閱讀用的窄衣服。
2. **畫面看起來簡陋。** 第一版的設計稿假設了 3 科目 × 3 章，真實資料是 1 科 1 章。書架這個隱喻需要「一排書」才成立，一本書的書架是一根棍子。設計沒有處理稀疏狀態 —— 而一個只有在資料很多時才好看的設計，在第一天就是壞的。

另外確認：中文筆畫密度遠高於拉丁字母，第一版把一套為拉丁介面設計的字級（大量 12–14px）直接套到中文上，實測在 FHD 螢幕上偏小。

被推翻的是**版面、字級、書架擺向、稀疏狀態**。資料模型、體檢規則、`bankHealth` 與 `dataLoader` 的介面、朱批的意象都不變。

## 設計方向：書架與目次

測驗區是「寫的那面」，題庫區是「收的那面」—— 同一個世界的兩個房間，不是兩棟房子。

科目是立在架上的書，**書背橫排並列在頁首下方**，直排中文。選一本，底下就是它的目次。兩區共用同一個書架與同一份目次骨架，只是目次的欄位不同：複習區每列是勾選框，題庫區每列是題數與狀態。

```
┌──────────────────────────────────────────────────────────────────────┐
│  問答題庫                                            複習 · 題庫      │
├──────────────────────────────────────────────────────────────────────┤
│  ┌──┐┌──┐┌──┐┌──┐                                                    │
│  │國││數││歷││英│   ← 橫排書架，書背直排                              │
│  │文││學││史││文│                                                     │
│  └──┘└──┘└──┘└──┘                                                    │
├───────────────────────────────────────────────┬──────────────────────┤
│  國文                                         │  概況                │
│  ─────────────────────────────────────────    │  4 科 · 42 章 · 981 題│
│  第一章  25    第八章  18    第十五章  22     │                      │
│  ─────────    ──────         ────────         │  朱批                │
│  第二章  30    第九章  25    第十六章  19     │  ┃ 成語運用           │
│  ──────────   ────────       ───────          │  ┃ 檔案不存在         │
│      ↑ 多欄目次，題數比例做成條目下的下劃線    │                      │
└───────────────────────────────────────────────┴──────────────────────┘
```

頁首兩區命名為 **複習 · 題庫**：用使用者要做的事命名，不用系統結構命名。

### 招牌元素：橫排書架與直排書背

這次唯一的大膽之處，理由是中文書本來就這樣上架，而科目本來就是「一本書裡有很多章」。技術上是 `writing-mode: vertical-rl`，範圍侷限在書架一處。

書背約 88px 寬、140px 高，科目名放大，底下用等寬字疊上「N 章 · M 題」。選中的書背往下推出數 px、底色轉為 `--accent-soft`；過場 160ms，`prefers-reduced-motion: reduce` 下不得位移，只換色。

3–6 個科目並排時書架約佔 528px，右側留空。真實書架本來就是書靠左、右邊留空 —— 那是誠實的，不是破綻。

**書架不出現在測驗頁**（`/quiz`）。作答中不該切換科目。

### 朱批即體檢，寫在書眉

朱批本來就是寫在**書頁邊上**的東西。全幅版面剛好生出了那條邊：右側書眉欄上半放概況、下半放朱批，固定可見。

這解決一個實際問題：20 章的多欄目次之後，若朱批接在目次下方，會被推到摺線以下，使用者根本看不到題庫壞了。

## 視覺系統

### 色：不新增任何色票

`src/index.css` 既有的色票已經定義了這個世界。區分靠**表面層次**，不靠新顏色：

| 角色 | token | 理由 |
|---|---|---|
| 題庫區背景 | `--surface-2` | 櫃子在紙的後面，比紙暗一階 |
| 目次紙、書眉欄 | `--surface` | 抽出來的那一本，浮在櫃子上 |
| 書背、選中態 | `--accent` | 沿用測驗區的松綠 |
| 體檢錯誤 | `--vermilion` | 朱批 |
| 體檢提醒 | `--ink-3` | 提醒不是錯誤，不該搶朱批的位置 |

暗色模式因此自動成立。

### 字：同一套字，兩種排法

字體不變（`--font-display` / `--font-body` / `--font-mono`）：

- 書背科目名、目次章名 → 襯線體。書背與目次是排版物，不是介面元件。
- 題數、id、統計數字 → 等寬。編目的聲音；測驗區的題號已在用等寬，語彙一致。
- 按鈕、表單、提示訊息 → 黑體。

行距：**複習區 1.9（給你讀），題庫區 1.55（給你掃）**。同樣的字，寬鬆的是文章，緊的是清單。

### 字級

`body` 必須改用 `1rem`，不得寫 px —— 寫 px 會蓋掉使用者在瀏覽器裡設定的字級偏好。次級文字下限拉到 `.875rem`。

| 元素 | 修訂前 | 修訂後 |
|---|---|---|
| 朱批小標 | `.75rem` | `.875rem` |
| 題數、統計 | `.78rem` | `.875rem` |
| 朱批內文 | `.86rem` | `.9375rem` |
| 導覽列 | `.88rem` | `.9375rem` |
| 目次章名 | 繼承 16px | `1rem` |
| 書背科目名 | `.98rem` | `1.125rem` |
| 頁面標題 | `clamp(1.1rem, 3vw, 1.35rem)` | `1.5rem` |

再加一階視窗級距：

```css
@media (min-width: 1600px) { :root { font-size: 112.5%; } }
```

以百分比而非 px 設定，使用者的瀏覽器偏好仍按比例生效。FHD（1920px）落在這一階，最小字因此從 12px 變為約 15.8px。

**不使用 `clamp()` 流體字級。** 視窗寬度與文字該多大之間沒有因果關係：把視窗拉窄字就縮小，讀起來反而更糟，而且它會打壞瀏覽器縮放。瀏覽器也量不到螢幕的物理尺寸 —— 15 吋 4K 筆電與 32 吋 4K 螢幕回報同樣的解析度卻需要相反的處理，所以「依解析度自動調整」在技術上沒有良好定義。能做的是給一個較大的基準、讓使用者偏好生效、再加一階粗略的視窗級距。

### 版面：全幅流動

不設 `max-width`。容器寬度 100%，左右留 `clamp(1rem, 3vw, 2.5rem)` 邊距。

| 區塊 | 尺寸 |
|---|---|
| 書架 | 橫排，書背 88 × 140px |
| 目次 | 佔剩餘寬度，多欄 |
| 書眉欄 | 固定 300px |
| 測驗題卡 | `max-width: 68ch`（維持可讀行長） |

**全幅不等於把文字拉長。** 2560px 螢幕上一行全幅中文約 150 字，可讀行長是 30–45 字，超過三倍會讓眼睛從行尾回不到下一行開頭。畫面用**欄位與結構**去填滿，閱讀區維持該有的寬度。

### 響應式

| 斷點 | 變化 |
|---|---|
| < 1100px | 書眉欄移到內容下方，目次減欄 |
| < 640px | 書架改橫向捲動、文字轉橫排；目次單欄；測驗頁進度軌移到題卡上方 |

頁面在任何寬度都不得出現橫向捲軸。書架是一組真正的 `<button>`，tab 順序與 `:focus-visible` 外框維持正常。

## 稀疏狀態

**版面對資料量負責，不假設資料量。** 這是第一版最大的失誤。

| 條件 | 呈現 |
|---|---|
| 科目 ≤ 2 | 書背加寬至 160px，吃掉水平空間 —— 一本書可以是一本大書 |
| 科目 ≥ 3 | 書背維持 88px |
| 章 ≤ 6 | 目次單欄，條目放大 |
| 章 7–14 | 目次兩欄 |
| 章 ≥ 15 | 目次三欄 |
| 全題庫僅 1 章 | 書眉欄補一句題庫檔案的位置（`public/data/`），讓那片空白在做事 |

這些門檻是純粹的資料量 → 版面決策，**抽成純函式**（`shelfDensity`、`tocColumns`）以便測試，不埋在 JSX 裡。

**絕不塞假資料撐場面。** 那是說謊，且一打開真實題庫就露餡。

## 體檢規則

檔案由 LLM 寫入，會漂移的就是這些：

| 檢查 | 嚴重度 |
|---|---|
| 章登記了但 JSON 抓不到（HTTP 非 2xx） | 錯誤 |
| JSON 語法壞掉 | 錯誤 |
| schema 驗證失敗（缺欄位、型別不對、選項不是 4 個） | 錯誤 |
| 檔案裡的 `chapterId` 與登記的不符 | 錯誤 |
| 章的 `subjectId` 指向不存在的科目 | 錯誤 |
| 同一章出現重複的 `id` | 錯誤 |
| 章有登記但零題 | 提醒 |
| 同一層級的 `order` 重號（排序結果不穩定） | 提醒 |

錯誤代表選到這章去複習會出事；提醒代表能用但不對勁。

### 刻意不做的檢查

**孤兒檔偵測（檔案存在但沒登記在 `index.json`）做不到。** 靜態託管的前端只能 `fetch` 指定路徑，無法列出 `public/data/questions/` 的目錄內容。要做只有兩條路：build 時用 Vite plugin 掃出 manifest 給前端比對，或把資料搬進 `src/` 用 `import.meta.glob`（但那會讓題目變成 bundle 的一部分，改題目就得重 build，與現行架構衝突）。

決定先不做：需要額外的建置設定，而檔案是由 Claude Code 代寫的，順手保持 `index.json` 同步比較省事。其餘八項檢查不受影響。

**題目品質不檢查。** 答案位置偏誤、tag 覆蓋率、解析長度等診斷統計不在本次範圍。

## 複習區的三欄

```
┌────┬──────────────────────────────┬──────────────┐
│ ▪  │  國文 總複習                  │  12 / 25     │
│ ▪  │                              │  答對 10      │
│ ▪  │  ┌────────────────────────┐  │              │
│ ◻  │  │ 03  弊／蔽／敝／蹩      │  │  錯題        │
│ ◻  │  │                        │  │  02  形近字   │
│ ◻  │  │ 下列哪個選項的用字…     │  │  07  破音字   │
│ ◻  │  │  A ……                  │  │              │
│ ◻  │  │  B ……                  │  │              │
│ ◻  │  └────────────────────────┘  │              │
└────┴──────────────────────────────┴──────────────┘
 進度軌          題卡 max 68ch          即時成績
```

- **左欄**：進度軌從細長條改成全高直欄，每題一格，看得到整份考卷的形狀。
- **中欄**：題卡維持 `68ch` 可讀行長。題卡內部（題幹、選項、朱批、成績單）已有完整樣式，本次不動。
- **右欄**：即時成績（已答 N/M、答對數）與**錯題即時累積** —— 答錯就往右欄加一筆（題號、tag）。

錯題即時累積沒有劇透問題：這個 app 是答完即批，錯題在當下就已經看過解析。`ScoreSummary` 結尾本來就會列錯題回顧，讓它邊答邊長等於把結尾那份清單攤在過程裡，右欄的內容也因此隨作答自然增加，不會從頭空到尾。

## 選題頁的書眉

右欄放「已選 N 章 · 約 M 題」、隨機排序開關、開始複習鍵，**固定可見**。20 章的多欄目次之後，把開始鍵放在目次下方會逼使用者捲到底才能開始。

顯示題數需要進場時抓取全部的章檔案（題庫區已經這樣做）。未來章數上百若感覺變慢，再改為在 `index.json` 增加 `count` 欄位、由題庫區負責驗證它與實際檔案是否一致 —— 但那要上游多寫一個會漂移的數字，在感受到效能問題之前不先付這個代價。

## 文案

照實說話，用使用者要做的事命名：

- 體檢無事 → 「題庫沒有問題。」
- 空章 → 「這一章還沒有題目。」空畫面是陳述，不是錯誤。
- 錯誤訊息指出是什麼、在哪裡，不道歉、不含糊：「`c-chengyu.json`：第 3 題的 `answerIndex` 缺少此欄位。」
- 同一個東西從頭到尾同一個詞，依 `CONTEXT.md`。

## 錯誤處理

- `index.json` 本身抓不到或格式錯 → 整頁顯示單一朱批，說明索引壞了；此時書架無法繪製，不嘗試部分渲染。
- 個別章出問題 → 該列標記狀態，詳情列在書眉的朱批區；其餘章照常顯示題數。
- 複習區沿用現行行為：載入失敗顯示錯誤訊息。體檢是題庫區的職責，不往複習區塞。

## 樣式重複的取捨

朱批的視覺（朱紅左邊線 + `--surface-2` 底）在 `quiz.css` 的 `.note` 已經有了。題庫區不 import `quiz.css` —— 那會讓題庫區耦合到測驗模組。改在 `bank.css` 用相同 token 寫一份，重複的是四行宣告，換來零耦合；兩者未來也可能各自演化（批改答案 vs 標記資料）。若出現第三個使用者再抽共用元件。

## 測試方式

沿用現行 TDD + Vitest。既有 73 個測試多為行為測試、不綁版面，改版後應大部分留存。

- `layout.test.ts` —— `shelfDensity` 與 `tocColumns` 的每個門檻與邊界（0、1、2、3、6、7、14、15 章）。純函式，測試密度最高。
